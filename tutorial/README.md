# stressbot 使用教程

面向压测使用者与部署者的操作手册：按"完成一件事"的顺序组织，每个示例都实际跑通过，每章末尾有"你应该看到什么"的验收标准。

- 想了解内部实现与全量字段：看[开发参考](../docs/README.md)与 [docs/](../docs/) 目录下的技术文档。
- 本教程与参考文档不一致时，以本教程为准。

## 环境准备

- Go ≥ 1.26（以仓库 `go.mod` 为准），能执行 `go run` / `go build`。
- 单机模式（第 1~12 章的主线）不需要 MySQL / Redis / 目标服务器也能跑通教学示例；接入真实协议后需要一台可连接的目标服务器。
- 分布式（第 13~14 章）需要 MySQL；Redis 按需。

## 建议阅读路径

- **压测使用者**：按 1 → 2 → 3 → 4 → 5 读完入门并写出第一个流程，再按需进入第 6 章之后。
- **部署者**：读 1 → 2，跳到第 13~14 章。

## 术语表

全书用词与下表一致；正文首次出现时都会回到这里。

| 术语 | 含义 |
|---|---|
| **机器人（Robot）** | 一个模拟的客户端实例。压测规模说"1 万机器人"就是 1 万个并发客户端。 |
| **流程节点（node）** | flow.json 里的一步：执行动作、循环、分支、等待等 9 种。"节点"在流程语境下都指它。 |
| **压测节点（Agent）** | 分布式形态里跑在一台施压机上的执行进程。为避免歧义，本书部署语境尽量说"节点机器/服务器"。 |
| **动作（action）** | 机器人做的一件事：发请求、建连接、等推送、写状态等 14 种 pattern。流程节点通过名字引用动作。 |
| **绑定（binding）** | 动作字段的取值规则：固定值、从状态取、随机生成等 17 种。 |
| **状态（state）** | 单个机器人的键值记忆。机器人编号、登录响应、脚本写入的数据都在这里。 |
| **监听（listen）** | 等待服务器主动推送的机制：先注册、后等待，推送先到也不丢。 |
| **服务名（service）** | 一条连接的名字（如 `logic`、`arena`）。动作通过服务名找到对应连接；codec 配置文件名也由它决定。 |
| **主连接（mainService）** | 以 mainService 服务名建立的连接。主连接意外断开时机器人停止。 |
| **心跳（heartbeat）** | 每条连接按配置周期发送的保活包，在 codec 配置里声明。 |
| **管理面** | 浏览器使用的 Admin Web 界面（HTTP，前缀 `/sbot/`）。 |
| **控制面** | Admin 与节点机器之间的 gRPC 长连接（下发任务、上报指标）。 |
| **资源下发** | 分布式形态下，proto/Lua/codec 等文件打包传到节点机器的机制。 |
