# 协议配置编辑器重新设计

- 日期：2026-06-23
- 范围：`cmd/web/src/components/modules/ProtocolConfigEditor.tsx` 及 `codecEditor/` 目录
- 类型：前端布局与文案重新设计（不改编辑语义、不改后端）

## 1. 背景与问题

协议配置编辑器（`ProtocolConfigEditor`）渲染在一个浮动窗口里，默认尺寸 **900×640**，最小 **600×400**（见 `EditorPage.tsx` 的 `FloatingWindow` 配置）。用户反馈当前排版存在三类问题：

1. **重要内容展示位置过小** —— 字段表 7 列挤在有限宽度里；字节尺（代码注释自称"主视觉与主校验工具"）被压成窄条。
2. **莫名其妙留出空白** —— ROUTE KEY 卡片只有一个输入框却占全宽，右侧大片留白；预览折叠后只剩标题行，下方空白。
3. **整体排版不合理** —— 不同重要性的区域被等宽平铺。

### 根因诊断

阅读全部相关组件后，定位到结构层面的根因：

- **单列垂直堆叠**：`pce-workspace` 是 `flex-direction: column` + `overflow:auto`，4 个工作台（FRAME / PIPELINE / ROUTE KEY / PREVIEW）全宽平铺。内容量差异极大（路由键只有一个输入框，帧布局有字节尺+字段表+详情），等宽堆叠必然"内容少→留白、内容多→挤压"。
- **字段表与字段详情上下堆叠且详情常驻**：`frame-edit-stack` 是纵向，表格 `scroll y:280` 写死高度，详情（`RoleLinkedForm`）常驻占位（未选中字段也有"空提示"占着）。只要"表格+详情"是两个并列常驻区，字段表就被挤压。
- **字节尺被埋没**：夹在帧参数和字段表之间，没给足空间。
- **预览折叠藏底**：验证能力发现性差。
- **文案违规**：标题与标注大量英文（FRAME / BYTE RULER / PIPELINE / ROUTE KEY / PREVIEW / `click span to select`），违反 CLAUDE.md「日志和错误信息使用中文」「UI 文本禁止暴露技术术语」。

## 2. 设计目标

- **用空间分配表达信息重要性**：帧布局（占 ~80% 编辑时间）> 管线 > 路由键 / 预览。
- **每个分区获得完整空间**，消除莫名留白。
- **字段表独占全宽舒展**，详情不抢占其横向空间。
- **标题中文、协议术语英文**：符合 CLAUDE.md 文案规范，同时保留与 `codec.json` 字段一一对应的协议术语，降低映射成本。

## 3. 已确认的设计决策（与用户逐项确认）

1. **主布局：分区标签页** —— 帧布局 / 管线 / 路由键 / 预览 各成一个 tab，每个 tab 获得完整的主舞台空间。否决了"单页网格"（640px 高度下仍会挤压）和"主舞台+侧抽屉"。
2. **文案：标题中文 · 协议术语英文** —— 分区导航标题全中文；`offset/size/type/endian/role/le/be` 等与 `codec.json` 字段对应的协议术语保留英文。
3. **帧布局：字段表全宽独占 + 详情行内展开** —— 否决了"字段表|详情左右双栏"（字段表 7 列最小宽 790px，塞进左栏必然横向滚动，是退步）。字段表独占全宽，详情作为选中行的行内展开（全宽、不抢横向、不选中时表格独占全部空间）。

## 4. 信息架构

四个分区 tab，按"编辑频率 + 内容量"分配：

| 分区 | 重要性 | 内容量 | 空间策略 |
|---|---|---|---|
| 帧布局 | 最高 | 大 | 默认 tab；帧参数顶栏 + 字节尺 hero + 字段表全宽（详情行内展开） |
| 管线 | 中 | 中 | 步骤卡片列表，卡片内分区小标题 |
| 路由键 | 低 | 小 | 双栏（模板编辑 ‖ 实时样例）填满 |
| 预览 | 中（验证） | 中 | 双栏（输入 ‖ 结果），不再折叠藏底 |

**校验徽标（增强项）**：每个 tab 标题可挂红点 + 问题数，一眼看到哪个分区有问题。依赖 `validateCodecSchema` 能按区域归类错误；若该改动成本过高，降级为顶部校验条全局展示（见 §7 风险）。

## 5. 全局骨架

```
┌───────────────────────────────────────────────────────────┐
│ 命令栏                                                     │
│ tcp:logic(大选择器) · 已保存  │  新建 复制 删除 │从基线│  导入 保存 清空  │结构│源码│
├───────────────────────────────────────────────────────────┤
│ 校验条（常驻紧凑）                                          │
│ ✓ 校验通过 · 启动时随连接下发            〔3 处问题 ▸〕     │
├───────────────────────────────────────────────────────────┤
│ 分区标签（带可选校验徽标）                                  │
│ [帧布局]   管线 ·1   路由键   预览                          │
├───────────────────────────────────────────────────────────┤
│                                                           │
│                    主舞台（随 tab 切换）                    │
│                                                           │
└───────────────────────────────────────────────────────────┘
```

- **命令栏精简**：连接选择器放大突出（它是"当前对象"，最重要）；操作按钮按语义分组，用竖分隔符隔开（连接管理 ‖ 文件操作 ‖ 视图切换）；单行优先，溢出才换行。所有命令逻辑（新建/复制/删除/导入/保存/清空/从基线载入）保留不变，只重组 UI 位置。
- **源码模式**：切到"源码"时隐藏分区标签栏，Monaco 占满主舞台（保留现有 `viewMode==='source'` 逻辑）。`errors.json` 视图继续强制源码、隐藏 tab 栏。

## 6. 各分区详细设计

### 6.1 帧布局 tab（核心）

```
┌─ 帧参数（紧凑顶栏，一行横排）──────────────────────────────────┐
│ 配置版本[1]  默认字节序[le小端│be大端]  header[8]B  trailer[0]B │
│                    length 计数范围 [不含header][不含trailer]    │
├─ 字节尺 hero（全宽 · 适中醒目）──────────────────────────────┐
│ 字节尺  ·  点击色块选中字段  ·  红色斜纹 = 越界或重叠           │
│ ╔══════════════════════════════════════════════════════════╗ │
│ ║      bodyLen        │ cmd │act│   index   │   (trailer)   ║ │
│ ║░░░░░░░░░░░░░░░░░░░░░│░░░░░│░░░│░░░░░░░░░░│░░░░░░░░░░░░░░║ │
│ ╚══════════════════════════════════════════════════════════╝ │
│ 0            4           5    6   8                          │
├─ 字段表（全宽独占 · 6 列舒展无横滚 · flex 撑满高）────[+ 添加]─┐
│ 字段名    offset  size  type   role    操作                  │
│▼ bodyLen    0      4    u32   length   ▲▼✕   ← 选中，已展开  │
│ ┌─ 字段详情（行内展开 · 全宽）─────────────────────────────┐ │
│ │ bodyLen  ·  角色 length  ·  字节序 [默认 le ▾]           │ │
│ │ 这个字段表示消息长度，计数范围由上方「length 计数范围」决定 │ │
│ └─────────────────────────────────────────────────────────┘ │
│   cmd       4      1    u8    route    ▲▼✕                  │
│   act       5      1    u8    route    ▲▼✕                  │
│   index     6      2    u16   value    ▲▼✕                  │
└──────────────────────────────────────────────────────────────┘
```

关键改动：

- **字段表全宽独占**：移除 `frame-edit-stack` 的上下堆叠；表格 `flex` 撑满主舞台剩余高度（去掉写死的 `scroll y:280`）。6 列在 ~860px 全宽下舒展，无横向滚动。
- **详情行内展开**：字段详情（`RoleLinkedForm`）不再是常驻第二区，而是 antd Table 的 `expandedRowRender`——选中某行时该行下方展开全宽详情面板，同一时间只展开一行（accordion）。未选中任何字段时，表格独占全部空间。
- **字节尺 hero**：strip 本体加高（现状 30px → 约 44px），刻度层与标签层完整，选中字段探针高亮。它是这个 tab 第一眼看到的视觉中心，但不过分（约 90–100px 整体高，不浪费）。
- **endian 移入详情**：字段表精简到 6 列（字段名 / offset / size / type / role / 操作）；`endian` 作为次要属性移入行内展开的字段详情（与 role 衍生配置 bits/source/from 同区编辑）。
- 列标题 `name` → `字段名`；其余协议术语列名保留英文。

### 6.2 管线 tab

保留 `PipelineEditor` 的步骤卡片逻辑，强化卡片内视觉分组。每张步骤卡片用明确的小标题分区，取代当前只有虚线 `Divider` 的分隔：

```
管线  ·  3 步  ·  encode 顺序，decode 自动反序            [+ 添加步骤]
┌ 步骤 1 · compress ──────────────────────── [▲▼✕] ┐
│ 基本属性： name│op│算法│onError│flag                │
│ ── 输入处理 ──  over(作用域) │ 算法参数              │
│ ── 输出与条件 ── produces │ when                    │
└──────────────────────────────────────────────────┘
```

充分利用 tab 完整宽度。算法清单加载、动态 params、when 子表单等逻辑不变。

### 6.3 路由键 tab

内容少，用双栏填满，消除留白：

```
┌─ 模板编辑 ─────────────┬─ 实时样例 ────────────┐
│ 模板中的 {name} 占位   │  样例 routeKey         │
│ 需对应 role:"route"字段 │  ┌──────────────────┐ │
│                        │  │ logic:1           │ │
│ [ {cmd}:{act}      ]   │  └──────────────────┘ │
│                        │  可用 route 字段：     │
│ 未知占位：(实时校验)    │  {cmd} {act}          │
└────────────────────────┴───────────────────────┘
```

左：模板输入 + 校验；右：实时样例 routeKey（大字等宽）+ 可用 route 字段清单。

### 6.4 预览 tab

从折叠藏底（`Collapse`）提升为独立 tab，双栏：

```
预览                  [编码 │ 解码]  TCP   调用后端真实引擎，不发起网络任务
┌─ 输入 ──────────────────┬─ 结果 ─────────────────┐
│ 路由字段  cmd[1] act[1]  │ 帧 hex                  │
│ body hex  [0a 2b ..]     │ 0a 00 2b ..  (可复制)   │
│ key hex   (可空)         │                         │
│          [  预览  ]      │ 字段解释                │
│                          │ bodyLen=43 cmd=1 ...    │
└──────────────────────────┴─────────────────────────┘
```

手动"预览"按钮触发（不自动）、错误双通道、纯编辑辅助等逻辑不变。

## 7. 命令栏与校验条

- **命令栏**：见 §5。连接选择器是视觉重点；按钮分组用 `Divider type="vertical"` 隔开。
- **校验条**：常驻、紧凑、单行。`liveErrors.length===0` 显示"校验通过"；有问题显示"N 处问题：首条"。问题多于 1 条时尾部 `Collapse` 展开全部。校验逻辑（`validateCodecSchema`）不变。

### 风险与降级

- **校验徽标按分区归类**：当前 `validateCodecSchema` 返回扁平错误字符串列表。要按"帧布局/管线/路由键"分区挂徽标，需让它返回带区域标记的错误（或前端按错误文本前缀归类）。若该改动牵涉后端校验逻辑、成本过高，则 **降级**：tab 不挂徽标，校验信息统一走顶部校验条（现状已可用）。此为增强项，不阻塞主布局交付。

## 8. 响应式

- 浮窗 600×400（最小）→ 任意拖大。
- **双栏退化为单列**：路由键 / 预览 tab 的左右双栏在窄窗（< 720px）退化为上下单列。
- **字节尺**：始终全宽，长 header 在条带内部横向滚动（现状逻辑保留）。
- **命令栏**：按钮组溢出换行。
- **字段表**：全宽；极窄时（< 600px）允许横向滚动（`scroll x: 'max-content'`）。

## 9. 文案规范

| 位置 | 文案 |
|---|---|
| 分区标签 | 帧布局 / 管线 / 路由键 / 预览 |
| 帧布局内小标题 | 帧参数 / 字节尺 / 字段表 / 字段详情 |
| 字节尺标注 | "字节尺 · 点击色块选中字段 · 红色斜纹 = 越界或重叠"（现状英文 `click span to select...` 改中文） |
| 字段表列名 | 字段名（原 name）/ offset / size / type / role（保留英文术语） |
| 校验条 | "校验通过 · 启动时随连接下发" / "N 处问题：…" |
| 操作按钮 | 新建 / 复制 / 删除 / 从基线载入 / 导入 / 保存 / 清空（保留现状中文） |

`offset/size/type/endian/role/le/be` 等协议术语、路由键模板占位 `{cmd}:{act}`、字段名本身保留英文（与 `codec.json` 一一对应）。

## 11. 数据流（不变）

单一数据源 = `content` 字符串。`parseCodecForEdit(content)` → `{ raw, schema, error }`。所有结构化编辑经 `codecEdit` helper 生成新 `content` → `onEdit(setContent)` → 重算 `parsed`。本次只动布局与文案，不改这一数据流，不改 `codecEdit`、`validateCodecSchema`、`parseCodecForEdit` 的语义。

## 12. 不改动什么（范围边界）

- 不改后端、不改 `services/` API 调用。
- 不改编辑语义（`codecEdit` helper、校验逻辑、`codec.json` 模板）。
- 不改新建/复制/删除/导入/保存/清空/从基线载入 的业务逻辑，只重组 UI 位置。
- 源码视图（Monaco）与 `errors.json` 视图保留。
- 不做无关重构。

## 13. 验证方式

1. `cd cmd/web && npx tsc -b` 无类型错误。
2. `cd cmd/web && npm run test`（Vitest）通过——注意 `codecEditor/__tests__/` 现有测试（`codecEdit.test.ts` 等）应不受影响（只动布局/文案）；若组件 props 签名变化需同步更新测试。
3. 前端 `npm run dev`，打开协议配置浮窗，逐项核对：
   - 4 个分区 tab 切换正常，每区无莫名留白。
   - 帧布局：字段表全宽舒展、选中行行内展开详情、未选中时表格独占全高。
   - 字节尺 hero 醒目、刻度完整、文案中文。
   - 路由键 / 预览 双栏填满。
   - 命令栏按钮分组清晰、单行优先。
   - 源码模式 tab 栏隐藏、Monaco 占满。
   - 窄窗（拖到 600×400）双栏退化为单列、无横向溢出。
4. 编辑一个连接配置 → 保存 → 重新打开，确认数据流闭环（content 字符串无损）。
