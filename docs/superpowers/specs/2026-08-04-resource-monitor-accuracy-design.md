# 资源监控准确性设计

## 目标

资源监控只展示当前任务实际使用节点的有效新鲜样本。采集失败、尚未建立差分基线、快照过期和无样本都使用 `null` 表达，不得伪装成 `0`。

## Agent 采集

- 继续使用 `gopsutil/v4`，不新增同类依赖。
- `SystemSnapshot` 使用明确口径字段：主机 CPU、主机内存字节、主机网卡字节速率、归一化进程 CPU、进程 RSS、Go heap、goroutine、线程和句柄/FD。
- 主机 CPU、进程 CPU、内存、RSS、线程、FD 和网络速率为可空字段；单项采集失败不污染其他指标。
- 主机 CPU、进程 CPU 和网络首轮只建立差分基线，第二轮才输出数值。
- 进程 CPU 按逻辑核心数归一化到整机容量的 0-100%，可与主机 CPU 同量纲比较。
- 内存和 RSS 以字节传输，避免 MB 截断参与聚合。

## Admin 聚合

- 系统资源聚合接收明确的节点 ID 集合；任务监控、采样和最终归档只统计该任务的分配节点。
- 新鲜度使用 Admin 收到报告的服务器时间，阈值为 `max(3 * systemInterval, 15s)`，不信任节点墙钟。
- 过期和缺失快照不进入数值聚合，并返回分配、有效、过期、缺失和覆盖率。
- CPU 与进程 CPU 按逻辑核心数加权；内存按精确字节加权。
- 平均值、最大值、网络速率、进程 RSS、线程和句柄在无有效样本时返回 `null`。
- 节点计数区分健康、异常和离线；总数始终是范围内分配节点总数。
- 返回当前最高主机 CPU、当前最高主机内存、当前最高进程 CPU、当前最高 RSS 和当前最高句柄的节点名称。

## 前端展示

- `/metrics` 必填计数字段做运行时有限数校验，缺字段直接判为无效响应，不做旧字段回退。
- 资源卡副标题使用系统资源有效样本覆盖率；动作窗口覆盖率放在吞吐卡。
- 标签明确为“主机 CPU 均值”“当前最高 CPU”“主机内存均值”“当前最高内存”。
- 主机网卡发送/接收只使用系统资源 API；动作业务字节不再冒充网卡流量。
- 单独展示“进程 CPU”“进程 RSS”“单节点最高句柄”。
- `null` 统一展示为 `—`，永不渲染 `undefined` 或把缺失值显示成 `0`。

## 测试

- Agent：首轮基线、单项失败、字节精度、进程 CPU 归一化、网络计数器回退。
- Admin：任务节点范围、新鲜度、字段级空值、加权平均、当前最高节点和覆盖率。
- 前端：缺失计数拒绝、系统/动作网络口径分离、空值展示模型和资源覆盖率。
- 完成后执行 Go race 测试、前端 Vitest、TypeScript/Vite 构建和 2-5 分钟运行日志检查。
