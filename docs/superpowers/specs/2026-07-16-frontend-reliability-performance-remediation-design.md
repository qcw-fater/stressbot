# 前端可靠性与性能问题修复设计

## 背景

本次修复来自对 `cmd/web` 全部前端代码的审查，重点覆盖三类问题：用户提示与代码注释是否准确、编辑与任务启动链路是否存在错误逻辑、以及流程编辑器和实时面板的性能瓶颈。

当前最明显的体验问题不是单一组件渲染慢，而是多个高频路径重复执行全量工作：普通字段输入会重建整张流程图并多次校验，状态键选项会重复扫描和加载脚本，日志与指标刷新会让大量组件同步更新。另有任务启动失败时提前清空旧监控数据、轮询连接状态相互覆盖、条件 Hook 等可靠性问题。

用户已确认采用“增量画布更新 + 150ms 防抖校验”的方案。本文档固化完整行为边界，作为后续实现与验收依据。

## 目标

1. 修复任务启动、轮询状态、Hook 顺序、拖拽状态更新等明确逻辑错误。
2. 普通表单输入不再触发整张 React Flow 画布重建。
3. 全局校验集中计算一次，并在连续输入期间以 150ms 防抖更新。
4. 降低状态键、日志、指标和浮动窗口的无效计算与渲染。
5. 保持 JSON 草稿输入允许处于暂时不合法状态，避免“必须每次击键都形成合法 JSON”的交互回归。
6. 统一用户可见文案和代码注释，移除已过时、暴露实现细节或概念混用的表述。
7. 修复本次审查发现的前端 lint 问题，并补充关键行为测试。

## 非目标

- 不重写 FlowEditor、TaskStartModal 等大型组件的整体架构。
- 不改变 `flow.json` 数据结构、后端 API 或任务状态机。
- 不把所有编辑器状态迁移到新的状态管理方案。
- 不追求一次性消除项目中所有可维护性问题，只处理审查确认且能独立验证的问题。
- 不改变已有日志数量上限、指标采样周期和流程持久化格式。

## 总体原则

### 原始状态与派生状态分离

用户输入首先同步写入流程业务状态，任何击键都不会因为校验防抖而丢失。画布节点、边、校验报告、状态键等属于派生数据，根据变更类型选择立即更新或延迟更新。

### 按变更类型更新

- 拓扑变更立即重建或更新画布，包括新增、删除、连接、断开、节点类型变化、控制流引用变化和加载完整流程。
- 影响当前节点显示的属性变更立即更新对应 React Flow 节点数据，但不重建无关节点和全部边。
- 仅影响表单内容、动作参数、监听参数的普通编辑只更新业务状态，并触发 150ms 防抖校验。
- 拖拽过程中只更新 React Flow 的临时位置；拖拽结束时再以不可变方式提交布局并触发持久化。

### 强一致操作不使用延迟结果

保存流程、导出 JSON、启动任务和替换当前画布时，必须取消待执行的防抖任务，基于最新业务状态同步生成完整流程并执行全量校验。按钮是否可用可以使用最近一次校验报告，但实际操作不能仅信任可能滞后的报告。

## 修复设计

### 1. 任务启动采用提交式清理

`startTask` 当前在脚本、协议配置、容量和网络等可失败检查之前清空旧监控数据。修复后分为两个阶段：

1. 预检阶段读取最新流程，完成同步校验、资源收集、脚本与协议配置检查、容量检查和请求数据组装，不修改旧监控数据。
2. 提交阶段在任务创建或启动确认成功后，才替换运行态画布、清空旧监控数据并安装新的指标数据源。

任何预检或远端启动失败都保留上一次任务的监控数据和当前编辑草稿，并展示原始错误信息。

### 2. FlowEditor 派生更新分层

移除 `updateAction`、`updateNode`、`updateListen` 对全量 `syncDerived` 的无条件调用。状态层提供明确的更新入口或变更标记：

- `content`：仅业务字段变化；更新对应节点的展示数据并安排校验。
- `topology`：节点和边关系变化；立即执行画布派生更新并安排校验。
- `replace`：载入、撤销重做、导入等完整替换；立即从完整流程重建画布并同步校验。

结构变更仍可复用现有 `jsonToFlow`，避免在本次修复中重写图转换算法。恢复节点位置时先建立 `Map<nodeId, position>`，消除逐节点 `.find` 形成的二次复杂度。

普通动作编辑只修补引用该动作的 React Flow 节点数据；普通监听编辑只修补引用该监听的节点数据；节点标签等自身属性只修补目标节点。若无法可靠确定影响范围，则退化为一次立即完整派生，保证正确性优先。

### 3. 校验集中化与防抖

增加单一的流程校验协调层，负责读取最新流程、状态键上下文并生成校验报告。Toolbar、ValidationReport 和节点错误标记只消费同一份报告，不再各自调用 `validateFlow`。

- 普通输入后 150ms 执行一次校验。
- 拓扑变更在画布更新后安排同样的校验；涉及必须立即反馈的非法连接时保留局部同步判断。
- 导入、撤销重做和完整替换立即校验。
- 组件卸载或新任务覆盖旧任务时取消旧计时器，防止过期报告回写。

撤销历史继续使用 Zundo；连续文本输入按现有或约 300ms 的批次合并，结构操作保持独立历史项。

### 4. 状态键选项只在依赖变化时重算

状态键 Provider 成为生产组件的统一数据入口。它只订阅生成状态键所需的最小状态，并使用稳定的脚本名签名判断依赖是否变化。仅当被引用脚本集合发生变化时从本地存储重新读取脚本；动作其他字段变化不触发加载。

Provider 输出稳定的基础状态键集合，具体表单只合并当前绑定等局部补充项。移除 Provider 内外同时运行的后备扫描路径，避免每个消费者再次订阅 nodes/actions/listens。

### 5. 多轮询源连接状态改为集合模型

EditorPage 不再让四个 `usePolling` 共享一个可互相覆盖的布尔值。改为按轮询源维护失败集合：

- 某个源失败时加入集合。
- 该源恢复时只移除自己的记录。
- 集合非空时显示连接异常。

连续失败、恢复和组件卸载都按源处理，因此一个接口恢复不会掩盖另一个接口仍不可用的事实。

### 6. Hook 顺序和副作用依赖修复

`BaselineSyncModal` 的所有 Hook 移到条件返回之前，确保 `hasConflicts` 从 false 变为 true 时 Hook 顺序不变。其余审查发现的缺失依赖、空 catch、无描述 `@ts-expect-error`、不必要 `any`、正则转义和导入类型问题逐项处理。

修复以行为等价为前提。需要稳定回调时优先缩小闭包依赖或使用稳定的 Zustand action，不通过关闭 lint 规则绕过问题。

### 7. 拖拽位置不可变提交

FlowCanvas 内新增、粘贴和自动布局等路径统一调用 store action 更新 `layout.nodePositions`，禁止直接修改 `getState()` 返回对象。拖拽中的高频 position change 不再克隆完整位置表；只更新 React Flow 运行态。拖拽结束后提交最终位置并触发一次持久化。

这一变化会让刷新或撤销时读取到的布局始终来自正式 store 更新，同时减少拖动大图时的对象分配。

### 8. 日志增量渲染

日志面板把“筛选结果”和“写入 Monaco”拆开：

- 过滤条件、日志来源或历史批次变化时执行一次完整重建。
- 轮询追加且过滤条件未变时，只处理新增条目并追加匹配文本。
- 同一刷新周期只过滤一次，不再先生成完整 join 字符串再判断是否可增量追加。
- 当环形上限淘汰旧日志或游标重置时，安全退化为完整重建。

移除用 `useMemo` 执行 ref 写入等副作用，改用事件路径或 `useEffect`。

### 9. 指标按节点订阅

指标 store 保存按节点 ID 可选择的数据，节点组件通过精确 selector 只订阅自己的指标。NodeShell 只订阅一次，再把结果传给纯展示的 MetricsBadge 和 Apdex 样式计算，避免同一节点重复订阅。

5 秒轮询更新时，仅指标值发生变化的动作节点重渲染；控制节点和无指标变化的节点保持稳定。展示含义、颜色阈值和采样周期不变。

### 10. 浮动窗口按用途管理生命周期

关闭只读且可重新请求数据的重型窗口时卸载 Monaco、ECharts 和历史详情等组件，释放事件监听和内存。存在未提交草稿的编辑窗口可以显式选择 `keepMounted`，或把草稿提升到 store 后再卸载。

默认采用关闭即卸载，只有确实需要保留未提交状态的窗口显式保活。重新打开只读窗口时允许重新加载数据，并保留必要的加载状态，避免展示旧任务内容。

### 11. JSON 草稿输入行为

保留 `JsonDraftInput` 的本地字符串草稿模型：输入 `{`、删除引号或暂时缺少右括号时，不向父级提交无效对象，也不阻止继续输入。合法 JSON 出现时按组件约定提交；失焦时若仍不合法，显示明确提示并保留可继续修改的草稿，不把内容强制重置成上一次合法值。

父组件因为其他字段变化而重渲染时，不覆盖正在编辑且尚未提交的草稿。仅当外部值确实发生变化且当前没有脏草稿时同步格式化文本。

### 12. 文案、注释与废弃 API

用户可见文本遵循项目约定：

- `Agent` 显示为“节点”。
- `Admin` 显示为“服务器”。
- `IDB` 或 `IndexedDB` 显示为“本地存储”。
- 不直接暴露 Lua、service/server、callback 等实现术语，分别按上下文使用“脚本”“连接服务”“监听”。

配置字段名、协议名和开发者错误详情可以保留原始英文，但必须附带可理解的中文语义。同步修正 FlowEditor、undo/redo、引用检查等文件中把 listens 写成 callback 的过时注释和变量名。

Ant Design 已废弃的 `Card.bodyStyle` 改为 `styles.body`，原生 `title` 提示改用 Ant Design Tooltip。大组件拆分只在支持上述修复且能降低风险时进行。

## 兼容性与失败处理

- `flow.json`、布局 JSON 和后端请求格式不变。
- 防抖只影响校验报告的出现时间，不影响输入值、画布结构、保存、导出和启动结果。
- 增量画布修补无法识别影响范围时允许完整重建，避免性能优化造成显示与业务状态不一致。
- 日志游标异常、来源切换和数据裁剪时允许完整刷新，优先保证内容正确。
- 窗口卸载后重新请求失败时显示现有错误态，不复用可能属于旧任务的内容。
- 指标 selector 必须对缺失指标返回稳定默认值，避免无指标节点产生额外渲染。

## 实施顺序

1. 为关键回归建立失败测试：JSON 草稿、任务启动清理、轮询失败集合、条件 Hook。
2. 修复任务启动与轮询状态等可靠性问题。
3. 分离 FlowEditor 原始状态、画布派生和集中校验。
4. 优化状态键 Provider 与拖拽布局提交。
5. 优化日志、指标和浮动窗口生命周期。
6. 统一文案、注释、废弃 API，并清理 lint 问题。
7. 执行完整验证和手工流程编辑器检查。

每一批先添加或调整测试，确认测试能复现旧行为，再实现修复并运行相关测试。若某批修改暴露前一批的设计假设不成立，先收紧当前批次，不同时扩展到无关重构。

## 测试与验收

### 自动化测试

- `JsonDraftInput`：连续输入不完整 JSON、恢复为合法 JSON、父组件重渲染、失焦错误提示。
- `startTask`：脚本、协议配置、容量或远端请求失败时不清空旧监控数据；成功后只清理一次。
- 轮询健康集合：两个源同时失败、其中一个恢复、全部恢复、组件卸载。
- `BaselineSyncModal`：无冲突和有冲突之间切换不产生 Hook 顺序错误。
- FlowEditor：普通字段编辑不调用全量图转换；拓扑变更立即更新；150ms 内连续输入只校验一次；强一致操作同步使用最新值。
- 状态键 Provider：动作普通字段变化不重新读取脚本；脚本引用集合变化时读取一次。
- 拖拽：过程中不提交完整布局，结束后不可变更新目标位置。
- 日志：稳定筛选条件下只追加新增匹配条目；来源、筛选和裁剪变化时完整重建。
- 指标：单个节点指标变化不触发无关节点 selector 结果变化。
- 浮动窗口：关闭后重型子组件卸载，显式保活窗口仍保留草稿。

### 完整验证

按仓库约定执行：

```text
go build ./...
cd cmd/web && npx tsc -b
cd cmd/web && npm run test
cd cmd/web && npm run lint
```

前端手工验收至少覆盖：

1. 打开当前 `conf/flow/flow.json`，校验报告无错误。
2. 连续编辑普通文本、数字、绑定和 JSON 字段，输入不中断且画布不明显卡顿。
3. 新增、删除、连线、拖拽、撤销和重做后画布与导出 JSON 一致。
4. 启动前预检失败时旧监控数据仍存在；启动成功后切换为新任务数据。
5. 同时模拟多个轮询接口失败，只有全部恢复后才隐藏连接异常。
6. 日志持续刷新、筛选和切换来源时内容正确且 Monaco 不做无意义全量替换。
7. 关闭并重新打开日志、趋势和历史窗口，确认资源释放、数据刷新和草稿保留行为符合设计。

本次只修改前端时不执行 Agent 运行 2 至 5 分钟的后端联调步骤；若实施过程中必须修改 Go 代码，则补充仓库规定的运行验证和日志审查。
